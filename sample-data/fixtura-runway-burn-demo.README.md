# Fixtura "Runway burn demo" data set

Generated by Fixtura (si2026-test-generator) to exercise Runway's burn engine
with an **in-progress** contract whose **funded dollars** run dry before the
period ends. One coherent contract across all files (same seed ties them).

## Files

| File | What it is |
|---|---|
| `fixtura-runway-burn-demo.award.sf26.pdf` | The signed award as a real filled **SF-26** (drop this into Runway's Ingest step) + the Section B fully-burdened labor-rate schedule |
| `fixtura-runway-burn-demo.contract.json`  | The same award as structured data — periods, CLINs, labor rates, ceiling vs. obligated, mod history |
| `fixtura-runway-burn-demo.timesheets.csv` | Weekly employee hours booked to the contract's labor CLINs (what Runway's "Sync now" pulls) |
| `fixtura-runway-burn-demo.labor.csv`      | Labor distribution export (bill rate × hours) |

The award is PIID **7026HEXDVC0001043** (DHS), T&M, ceiling **$8,701,569.60**,
obligated **$5,608,002.71** (64% funded). Labor CLINs 0001 + 0002; travel/ODC
CLINs 0003 + 0004.

## How it was generated (reproducible)

Fixtura preset generation, **seed 42**. The award (`govcon_award_sf26`) uses:

```json
{ "pop_in_progress": true, "option_years": 0, "contract_type": "T&M" }
```

The timesheet / labor exports (`govcon_timesheet`, `govcon_labor_export`) add
one more opt so the roster is crewed to the plan and burns on plan:

```json
{ "pop_in_progress": true, "option_years": 0, "contract_type": "T&M", "staffing": 1.0 }
```

- `pop_in_progress` — anchors the base period to the present, so the contract is
  mid-flight (today ≈ week 21 of the 52-week base year) and every timesheet week
  falls inside the period.
- `option_years: 0` — a single base year, so the obligated-vs-ceiling gap lands
  inside the period Runway is watching.
- `contract_type: T&M` — a labor-hours contract, the burn case.
- `staffing: 1.0` — sizes the roster to the contract's planned FTEs (~24 people)
  so the logged hours actually burn the contract on plan. Without it Fixtura
  fields one person per labor line and the contract reads far under budget.

Timesheets were pulled at **460 rows** (≈ one weekly timesheet per person across
the in-progress weeks). Runway's "Sync now" uses these same opts + row count by
default (`server/app/sources.py`).

## Expected tripwire (funding-aware engine)

Runway measures runway against the **funded** dollars, not just the ceiling
(FAR 52.232-22, Limitation of Funds). On this set the burn engine flags:

- **CLIN 0001** — funded ≈ $2.25M, funds exhaust **≈ week 34** (~89 days runway)
- **CLIN 0002** — funded ≈ $2.99M, funds exhaust **≈ week 36** (~107 days runway)

Both fire ~16–18 weeks before the period-of-performance end date. Contract
overall reads ≈ 37% burned at week 21.

## To regenerate / vary

Re-run Fixtura `generate_preset(...)` with the opts above (or POST them to
`/generate` / `/export`). Dial `staffing` down (e.g. `0.5`) for an
under-burning contract or up (`1.2`) for a hot one; the tripwire week moves with
it.
